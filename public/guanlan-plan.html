客户与核心问题

先说清楚我们为谁、解决什么。

客户画像

新能源企业（本方案以储能企业为样例）的三类团队共同使用观澜：

团队日常工作在观澜里的角色
战略团队决定未来几年进入哪些区域、哪些细分市场看区域机会对比与布局决策案，做取舍
市场团队跟踪政策、招投标、竞品动态，寻找商机在情报总览里过滤信号、发起深度研究
业务拓展团队对接具体项目、判断真假、推进签约落地用项目核验台确认项目成色，避免空转

三个核心问题（客户的原话）

  • "市场热度难辨真伪。"政策一出媒体全在欢呼，但政策支持不等于真实付费需求；项目签约不等于投产并网。团队缺一个把"虚热"和"真实需求"分开的尺子。
  • "项目进展缺少核验。"外部新闻里项目遍地开花，实际推进情况没人盯、没法验证，把签约新闻当需求证据会误判整个区域。
  • "外部趋势与内部能力难以关联。"研究报告能说清"哪里市场大"，说不清"我们干得了吗"；市场、技术、区域团队信息各管各的，结论拼不成一张图。
一句话定义核心问题：新能源企业缺的不是信息，而是一条从「原始信号」到「可执行的布局决策」的完整加工链——能让真假分明、内外关联、持续更新的研究闭环。
贰

方案总览

观澜是什么、不是什么。

观澜是一个产业情报研究工作台：把外部情报（能源政策、招投标、项目公告、行业数据）与内部资料（客户访谈、上下游交流、实地调研、内部项目档案）汇入同一个研究闭环，持续输出三类成果——核验过的项目事实、可对比的区域机会、可执行的布局决策案——并在重要变化出现后自动触发研究更新。

方案价值（对应三个核心问题）

核心问题观澜的解法价值量化（目标）
热度真伪难辨双信号比对：媒体热度 vs 经核验的需求信号，逐项显示差距区域误判率下降，避免在"虚热"区域重仓
项目缺核验四段核验链（签约属实→审批备案→建设核验→并网投产），走通才算真无效项目跟进减少 50% 以上，BD 团队时间投向真实项目
内外难以关联外部机会 × 内部能力对齐视图，缺口显式化为"成立条件"决策案自带"干不干得了"的答案，立项论证周期从月级缩到周级

产品边界（明确不做）

  • 不是聊天机器人：不提供开放式问答，所有产出都是结构化、可溯源的研究结论。
  • 不是单页看板：看板只是入口，背后是「情报 → 核验 → 研究 → 决策 → 更新」的完整业务流程和多个关联界面。
  • 不替代人的判断：系统给证据和推演，决策由人签署；每一次人工复核都留痕。

业务流程：情报如何变成决策

一条持续运转的研究闭环，五个环节缺一不可。

① 归集 → ② 核验 → ③ 研究 → ④ 决策 → ⑤ 更新 ↺ 回到 ①

环节做什么关键规则
① 归集外部信源自动抓取入库；内部访谈纪要、调研影像、项目档案人工归档每条情报打三类标签：来源（外部/内部）、区域、影响维度（需求/竞争/政策/落地）
② 核验项目走四段核验链；情报做跨信源交叉印证至少两个独立信源印证才能进入研究引用；单源信息标"待交叉"，不得作为结论依据
③ 研究区域机会评分（五维）、竞争格局梳理、进入条件清单每个分数可下钻到支撑它的具体情报条目；内外信源各占一定权重
④ 决策机会 × 内部能力对齐，输出布局决策案结论版本化；每条建议附成立条件（什么条件下成立）与退出线（什么信号出现就撤）
⑤ 更新重要变化（新政策、竞品降价、项目降级）自动触发复核更新全程留痕：谁触发、改了什么、依据是什么；重大更新需人工复核签署
这条闭环正是对题目"贯通持续情报积累、深度分析与业务判断，并支持重要变化出现后的研究更新"的直接回答。演示时我们将现场触发一条模拟政策事件，展示 ⑤ → ④ 的完整链路。

产品页面设计说明

五个业务界面，各对应流程中的环节；配套可交互原型 Demo（观澜-产品原型demo.html）。

界面 ① 情报总览（对应环节 ①②）

  • 顶部四张 KPI 卡：在跟踪项目数、重点区域数、本月新政策、结论更新次数——点卡片直接跳转对应界面，是整个工作台的"今日待办"。
  • 情报流：内外信源统一成一条时间流，每条标注信源类型与印证状态（待交叉 / 双源印证 / 三源印证）；点击任意条目展开侧滑详情，看它的来源、交叉印证情况和已触发的研究动作。
  • 热度真伪扫描：并列显示"媒体热度"与"经核验的真实需求信号"，两根条的差距可视化呈现"虚热"程度——这是解决痛点一的直接界面。
  • 内外信源结构：当前研究引用里外部/内部信源的占比，防止研究沦为纯二手信息汇编。

界面 ② 项目核验台（对应环节 ②）

  • 四段核验链：签约属实 → 审批备案 → 建设核验 → 并网投产。每段点亮需要对应的证据（公告、批复文件、实地影像、并网公示）。
  • 状态筛选：全部 / 进展存疑 / 已核验 / 新入库；"进展存疑"是 BD 团队最常用的一格。
  • 行级详情：点击项目展开核验进度、最近信源动作与自动判定理由；判定由规则引擎给出，人工可申诉复核。

界面 ③ 区域机会对比（对应环节 ③）

  • 区域选择器：点选任意两个区域横向对比，主选区（绿）与对比区（琥珀）。
  • 五维对比条：需求真实度、落地转化率、政策稳定度、渠道匹配度、盈利空间——每个维度由多条已核验情报加权得出，可继续下钻。
  • 进入条件清单：选中区域要进场必须满足的条件（渠道、资质、价格、运维），把抽象的"机会分"翻译成具体的"要做什么"。
  • 研究判断卡：结构化结论（推荐布局 / 观察仓 / 跟踪仓 / 暂缓），一键带入布局决策案。

界面 ④ 布局决策案（对应环节 ④）

  • 四步决策流：机会识别 → 能力对齐 → 风险界定 → 立项论证，横向流程图呈现，点击节点查看该步骤的说明。
  • 内部能力对齐检查：渠道、产品、资金、运维、政企五项能力逐项打分，绿（匹配）/ 琥珀（部分匹配）/ 红（缺口），缺口不掩盖、直接写进成立条件——解决痛点三的核心界面。
  • 决策结论区：版本化结论 + 编号的成立条件（如"3 个月内组建本地运维点，否则降级为渠道合作模式"）与退出线。

界面 ⑤ 变化与更新（对应环节 ⑤）

  • 事件响应链路：重要变化进入后，自动生成复核任务 → 重算模型 → 调整评分 → 人工复核 → 决策案版本升级，每一步标注"自动/人工"与依据。
  • 历史更新留痕：所有历史结论变更按时间排列，标明影响了哪几项结论——研究"敢更新、可追责"。
  • 现场演示按钮：原型内置"模拟江苏新版分时电价政策"事件，评委可亲手触发，完整看到事件如何传导为决策案 v1.4 → v1.5 的变化。

贯穿全局的交互原则

  • 一切可下钻：屏幕上任何一个数字、任何一条结论，点开都能看到支撑它的原始信源——"关键结论有据可查"落实为交互行为而非口号。
  • 内外同屏：每个界面都同时出现外部信号与内部资料，物理上强制"关联"。
  • 变更显性化：结论的每次变化都可见、可追，版本号永远醒目。

情报体系与核验规则

跨信源、比较核验——研究可信度的地基。

信源清单

类别信源采集方式
外部 · 政策发改委/能源局文件、征求意见稿、终稿自动抓取 + 政策研读简报
外部 · 招投标公共资源交易平台、央企电商化采购平台自动归集，按区域/规模结构化
外部 · 项目公告环评公示、并网公示、延期公告自动归集 + 与核验链字段对齐
外部 · 行业数据行业与技术公开数据、媒体报道自动归集，仅作热度信号，不单独作证据
内部 · 访谈客户访谈纪要、上下游交流记录人工归档，模板化标注关键信号
内部 · 调研实地影像、现场记录人工归档，作为核验链第三段证据
内部 · 档案历史项目资料、测算模型台账结构化入库，供能力对齐与收益重算调用

核验规则（研究引用的准入门槛）

  • 双源原则：进入研究引用的信息，须至少两个相互独立的信源印证（内外各一更佳）。纯媒体转载视为单源。
  • 内外交叉：区域"需求真实度"评分必须同时含外部证据（招投标/公告）与内部证据（访谈/调研），任何一侧缺失自动降级为"待研"。
  • 核验链准入：只有走完四段核验链的项目才能作为"落地转化率"的正面样本；未走通的项目计入"存疑"，不贡献需求证据。
  • 模拟资料标注：原型中所有演示数据均标注"模拟"，真实交付时替换为客户实际信源。

深度研究案例设计

以储能企业为例：比较不同区域的市场机会与进入条件，并跟踪新信息对布局判断的影响。

案例课题

"华东 vs 华东之外：一家工商业储能企业的区域布局论证"——以江苏为主选、浙江/山东为对比，完成一次从原始情报到布局决策案的全链路研究，作为产品演示的实证底稿。

案例的三层结论结构

层次内容在产品中的落点
事实层126 个在跟踪项目的核验状态、9 条本月新政策的信号强度情报总览 + 项目核验台
判断层江苏 8.2 / 浙江 7.4 / 山东 6.5 的机会分及五维拆解、进入条件清单区域机会对比
决策层优先布局江苏工商业储能 + 三条成立条件 + 退出线，v1.4 版决策案布局决策案

变化跟踪设计（案例的"活"的部分）

案例不止于静态结论：内置三个已发生的历史变化（山东项目降级、竞品降价、客户访谈印证）和一个可现场触发的模拟变化（江苏分时电价新政），完整展示"新信息 → 结论更新"的传导，证明研究是持续的服务而非一次性的报告。

商业可行性

谁付费、为何持续付费、如何验证价值。

谁付费

付费主体是新能源企业的战略/市场部门（年费订阅），以"席位 + 信源接入数"计价；对业务拓展需求重的企业叠加"项目核验"增值模块。试点期以单区域研究包（如"华东储能区域包"）低门槛切入。

为何持续使用（而非一次性报告）

  • 价值在更新里：政策、竞争、项目每天都在变，一次性报告三周后即贬值；观澜的结论始终是"当前版本"。
  • 沉淀在客户自己身上：访谈纪要、调研影像、内部档案入库越多，内外关联越准，形成数据护城河——换工具等于丢掉积累。
  • 嵌入例会：布局决策案的版本更新节奏与战略例会对齐，成为会议材料本身，而非额外的系统。

如何验证商业价值

验证方式说明
决策回溯对照每季度回看：使用观澜做出的布局判断 vs 未使用时的假设判断，量化避免的误判（如"虚热"区域投入）
BD 效率指标无效项目跟进占比、项目从接触到确认成色的时间
使用黏性周活跃研究者数、情报下钻次数、人工复核响应时长

四 · 整合与演练第 4 周前半撰写综合业务方案（本文档）；补齐商业可行性论证；全部模拟资料标注检查方案文档定稿；诚信标注清单
第 4 周后半按评分权重排演：痛点（30%）→ 研究与核验（30%）→ 产品演示（25%）→ 商业（15%）；两轮全流程彩排15 分钟演示剧本 + 备用问答手册
排期的核心取舍：先研究、后原型（第 2 周不写代码）。研究底稿的真实性决定产品演示的说服力——界面可以迭代，研究的可信度无法临时补。
